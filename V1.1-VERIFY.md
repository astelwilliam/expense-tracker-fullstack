# V1.1 verification checklist (Windows PowerShell)

Keep your *existing* project and `.env` values. Test this ZIP in a new folder.
This ZIP has no actual `.env`, database credentials, or `node_modules`.

## Backend

```powershell
cd server
npm ci
# Copy over your existing server/.env securely, or create from .env.example.
npm test
# If your Windows DNS still cannot query Atlas SRV records:
node -e "require('node:dns/promises').setServers(['8.8.8.8', '1.1.1.1']); import('./src/server.js')"
```

Check http://localhost:10000/api/health. Never share your `.env`.

## Frontend

```powershell
cd client
npm ci
Copy-Item .env.example .env.local
npm run lint
npm run build
npm run dev
```

## Manual acceptance

1. Sign in as test user. Make an Expense of 250.50, then Income of 5000.
2. Confirm balance 4749.50; editing type changes the signed value.
3. Change transaction date to last month; monthly card no longer includes it.
4. Search by title, category, type, date range; clear filters.
5. Refresh page, log out/in, restart server; transactions persist.
6. Use a separate test user to verify no cross-user leakage.
7. Edit and delete a disposable transaction; confirm changes persist.
8. Run `npm audit --omit=dev` independently in client and server. Review findings before any public deployment. Do not run `npm audit fix --force` without reviewing dependency changes.

The legacy root frontend is unchanged. Production deployment remains pending these checks and rotation of any exposed credentials.
